## 1. 约束体系总览

本项目按 **Harness Engineering** 范式组织开发与执行：**模型提供智力，Harness 提供控制**。
核心原则——不依赖 prompt 软约束，而是用**工具与代码机械强制**架构规则；仓库是代理工作的唯一接口。

```

│                    约束体系（Harness）                       │
│  ┌───────────┐ ┌───────────┐ ┌───────────┐ ┌───────────┐  │

```

## 2. 架构约束（机械强制）

### 2.1 分层与依赖模型

```
pms-api (Controller/Interceptor/Aspect/Config)
    ↓ 依赖
pms-service (业务逻辑，按业务域分包)
    ↓ 依赖
pms-dao (Entity/Mapper/Flyway)
    ↓ 依赖
pms-common (DTO/VO/常量/枚举/异常/工具)
```

**允许的边**（有限集合，ArchUnit 强制）：
- Controller → Service ✅
- Controller → common ✅
- Service → Service（跨域走对方 Service）✅
- Service → Mapper ✅（本域）
- Service → common ✅
- Aspect → Mapper（操作日志切面）✅
- Mapper → Entity / common ✅

**禁止的边**：
- Controller → Mapper / Entity ❌（R03/R04）
- Service → Controller ❌（R08）
- Service → pms-api ❌
- dao / common 反向依赖上层 ❌
- 跨业务域直调他人 Mapper（走对方 Service）❌（R11，存量例外登记）

### 2.2 命名规范（ArchUnit 强制）

| 层 | 后缀 | 例外 |
|----|------|------|
| Controller（`..controller..`） | `*Controller` | — |
| Service（`service..` 顶层类） | `*Service` | `*Helper`（config 基础设施：TransactionHelper 等） |
| Mapper（`dao.mapper..`） | `*Mapper` | — |
| Entity / DTO | 表名/模块名大驼峰 | — |
| 常量 / 枚举 | `*Constants` / `*Enum` | — |

### 2.3 数据与业务硬约束（AGENTS.md 内联）

多酒店隔离（hotel_id 取 `UserContext.getHotelId()`，禁硬编码）、金额 BigDecimal（禁 float/double）、
账务流水只增不改（REVERSAL 冲账）、防超卖、编号唯一、夜审分布式锁、逻辑删除、敏感加密、Flyway 迁移。

## 3. 机器强制载体

| 载体 | 位置 | 强制内容 | 运行方式 |
|------|------|----------|----------|
| ArchUnit | `pms-api/src/test/java/com/hotel/pms/arch/ArchitectureTest.java` | 分层/命名/金额类型（R01~R09） | `mvn test` / `mvn verify` |
| Flyway | `pms-dao/src/main/resources/db/migration/V*.sql` | 结构变更唯一入口，checksum 保护 | `mvn verify` |
| CI | `.github/workflows/ci.yml` | backend-ci + frontend-ci，main 分支保护 | push/PR 自动触发 |
| 本地验证 | `tools/verify-local.ps1` | 后端 verify + 前端 build 一键全量 | 本地手动 |
| 规则注册表 | `.harness/rule-registry.md` | 机器强制规则 + 存量违规台账 | 每次交付更新 |

## 4. 收敛机制（Entropy Management）

Harness 的核心是**收敛**：约束评估 → 缺口识别 → 规则细化，直到结构幂等（重复执行不再产生新变更）。

- **存量违规**：rule-registry V-01~V-05 登记，ArchUnit 排除名单豁免，修复后删除豁免。
- **教训库**：`.harness/lessons.md`，错误 → 根因 → 固化载体 → 状态。
- **失败复盘**：`.harness/failure-review.md`，每次失败四问（约束是否定义/是否可机器强制/是否有测试/是否收敛）。
- **完成清单**：`.harness/checklist.md`，PR 前逐项自查。
- **Backlog**：`.harness/backlog.md`，功能开发 + 存量治理优先级。

## 5. 开发工作流

```
拉分支 (feat/<模块>-<简述>) → 开发（遵守 AGENTS.md 硬约束）
→ 自查 (.harness/checklist.md)
→ 本地验证 (tools/verify-local.ps1 全绿)
→ 提交 (Conventional Commits)
→ push → 创建 PR → CI 全绿 (backend-ci + frontend-ci)
→ 合入 main（受保护分支）
→ 收敛：更新 rule-registry / lessons / backlog
```

## 6. 存量合规基线（2026-09-15 审计）

| 项 | 结果 |
|----|------|
| 模块依赖方向 api→service→dao→common | ✅ 合规（pom 依赖正确） |
| Service 反向依赖 api | ✅ 0 处 |
| Entity/DTO 浮点字段 | ✅ 0 处 |
| Controller 直调 Mapper | ❌ 1 个类（UserController，V-01） |
| Controller 直用 Entity | ❌ 8 个类（V-02，ArchUnit 实测） |

| 跨域直调 Mapper | ❌ 1 处（ReportServiceImpl，V-04） |
| 源码目录备份文件 | ❌ 20+ 个（V-05） |
| 前端引用不存在的 API | ❌ 1 处（V-07，**本次已修复**，npm run build 通过） |
| git / 测试 / CI | ❌ 本次补齐（git init + ArchUnit 9 规则 + CI + verify-local） |

治理优先级：V-01~V-03、V-06（P0，违反分层与多酒店隔离）→ V-04（P1）→ V-05（P1）。
