## 1. 总则

### 1.1 测试目的
- 保证代码质量和功能正确性
- 及早发现和修复缺陷
- 防止回归问题
- 提高代码可维护性

### 1.2 测试原则
- **独立性**：每个测试用例相互独立，不依赖执行顺序
- **可重复**：测试结果可重复，不受环境影响
- **自验证**：测试自动判断通过/失败，无需人工确认
- **及时性**：代码提交前必须通过所有测试


### 1.3 强制测试要求（必须遵守）

> **核心规则：每个后端功能完成后，必须编写并运行单元测试，测试通过后才能提交代码。**

#### 强制测试清单

| 序号 | 要求 | 说明 |
|------|------|------|
| 1 | **Service层必须测试** | 每个Service类的每个public方法必须有对应的单元测试 |
| 2 | **正常流程必须测试** | 主要业务逻辑的正常执行路径必须测试 |
| 3 | **异常流程必须测试** | 参数校验失败、业务异常等异常场景必须测试 |
| 4 | **边界条件必须测试** | 空值、最大值、最小值等边界情况必须测试 |
| 5 | **测试必须通过** | 所有测试用例必须通过，才能提交代码 |

#### 测试覆盖率要求

| 模块 | 最低覆盖率 | 说明 |
|------|------------|------|
| Service层 | **100%** | 核心业务逻辑必须全覆盖 |
| Controller层 | **80%** | 主要接口必须测试 |
| Mapper层 | **60%** | 复杂SQL必须测试 |

#### 测试完成检查清单

**功能开发完成后，必须确认以下内容：**

- [ ] Service层所有public方法是否有对应的单元测试
- [ ] 正常流程是否测试
- [ ] 异常流程是否测试（参数校验、业务异常）
- [ ] 边界条件是否测试
- [ ] 所有测试是否通过
- [ ] 测试覆盖率是否达标

**代码提交前检查：**

- [ ] 运行 mvn test 确认所有测试通过
- [ ] 运行 mvn test jacoco:report 确认覆盖率达标
- [ ] 测试代码是否符合命名规范
- [ ] 测试代码是否有清晰的注释

#### 测试命名规范

`
test{方法名}_{场景}_{预期结果}
`

**示例：**
- 	estCreate_Success - 创建成功
- 	estCreate_DuplicateFloorNo - 楼层号重复
- 	estGetById_NotFound - ID不存在
- 	estUpdate_NullParam - 参数为空

### 1.4 测试分层
`
单元测试（Unit Test）      → 快速、隔离、测试单个类/方法
    ↓
集成测试（Integration Test） → 测试模块间交互、数据库操作
    ↓
端到端测试（E2E Test）      → 测试完整业务流程（可选）
`

## 2. 单元测试规范

### 2.1 测试类命名规范

| 被测试类 | 测试类 | 示例 |
|----------|--------|------|
| SysAccountService | SysAccountServiceTest | SysAccountServiceTest |
| AuthService | AuthServiceTest | AuthServiceTest |
| RoomController | RoomControllerTest | RoomControllerTest |

**规范**：
- 测试类放在 src/test/java 下，与被测试类相同的包路径
- 测试类名 = 被测试类名 + Test
- 测试方法名 = 	est + 被测试方法名 + 场景描述

### 2.2 测试方法命名规范

**格式**：	est{方法名}_{场景}_{预期结果}

**示例**：
`java
// ✅ 正确的命名
testGetById_当ID存在时_返回账号信息()
testGetById_当ID不存在时_抛出业务异常()
testLogin_当用户名或密码错误时_抛出业务异常()
testLogin_当账号被锁定时_抛出业务异常()

// ❌ 错误的命名
testGetById()
testLogin()
test1()
`

### 2.3 测试方法结构规范

**AAA模式**（Arrange-Act-Assert）：
`java
/**
 * 测试根据ID查询账号
 * <p>
 * 场景：账号ID存在
 * 预期：返回账号信息
 * </p>
 */
@Test
void testGetById_当ID存在时_返回账号信息() {
    // ========== Arrange（准备） ==========
    // 准备测试数据
    Long accountId = 1L;
    SysAccount expectedAccount = new SysAccount();
    expectedAccount.setId(accountId);
    expectedAccount.setUsername("admin");
    expectedAccount.setPassword("encrypted_password");
    
    // Mock依赖
    when(accountMapper.selectById(accountId)).thenReturn(expectedAccount);
    
    // ========== Act（执行） ==========
    // 调用被测试方法
    SysAccount actualAccount = accountService.getById(accountId);
    
    // ========== Assert（断言） ==========
    // 验证结果
    assertNotNull(actualAccount);
    assertEquals(expectedAccount.getId(), actualAccount.getId());
    assertEquals(expectedAccount.getUsername(), actualAccount.getUsername());
    
    // 验证方法调用
    verify(accountMapper).selectById(accountId);
}
`

### 2.5 断言规范

**使用JUnit 5断言**：
`java
// 相等断言
assertEquals(expected, actual);
assertEquals(expected, actual, "自定义错误消息");

// 非空断言
assertNotNull(actual);
assertNotNull(actual, "对象不应为空");

// 布尔断言
assertTrue(condition);
assertFalse(condition);

// 异常断言
assertThrows(BusinessException.class, () -> {
    accountService.getById(999L);
});

// 超时断言
assertTimeout(Duration.ofSeconds(1), () -> {
    accountService.process();
});
`

**使用AssertJ断言（推荐）**：
`java
import static org.assertj.core.api.Assertions.*;

// 链式断言
assertThat(actual)
    .isNotNull()
    .hasFieldOrPropertyWithValue("username", "admin")
    .hasFieldOrPropertyWithValue("status", "ACTIVE");

// 集合断言
assertThat(list)
    .hasSize(3)
    .extracting("username")
    .contains("admin", "user1", "user2");

// 异常断言
assertThatThrownBy(() -> accountService.getById(999L))
    .isInstanceOf(BusinessException.class)
    .hasMessage("账号不存在");

### 3.3 Mock规范

**Mockito使用规范**：
`java
@ExtendWith(MockitoExtension.class)
class AuthServiceTest {
    
    @Mock
    private SysAccountMapper accountMapper;
    
    @Mock
    private PasswordEncoder passwordEncoder;
    
    @InjectMocks
    private AuthService authService;
    
    @Test
    void testLogin() {
        // ========== Arrange ==========
        // 准备测试数据
        LoginDTO loginDTO = new LoginDTO();
        loginDTO.setUsername("admin");
        loginDTO.setPassword("123456");
        loginDTO.setCaptcha("1234");
        loginDTO.setCaptchaKey("key123");
        
        // Mock查询结果
        SysAccount mockAccount = TestDataBuilder.buildSysAccount();
        when(accountMapper.selectByUsername("admin")).thenReturn(mockAccount);
        
        // Mock密码验证
        when(passwordEncoder.matches("123456", "encrypted_password")).thenReturn(true);
        
        // ========== Act ==========
        LoginVO result = authService.login(loginDTO);
        
        // ========== Assert ==========
        assertNotNull(result);
        assertNotNull(result.getToken());
        
        // 验证方法调用次数
        verify(accountMapper, times(1)).selectByUsername("admin");
        verify(passwordEncoder, times(1)).matches("123456", "encrypted_password");
    }
}
`

**Mock场景规范**：
`java

    .thenReturn(value1)

verify(mock, atLeastOnce()).method();

## 4. 测试覆盖率要求

### 4.1 覆盖率标准

| 模块 | 行覆盖率 | 分支覆盖率 | 说明 |
|------|----------|------------|------|
| Service层 | ≥ 80% | ≥ 70% | 核心业务逻辑 |
| Controller层 | ≥ 70% | ≥ 60% | 接口层 |
| Mapper层 | ≥ 60% | ≥ 50% | 数据访问层 |
| 工具类 | ≥ 90% | ≥ 80% | 公共工具类 |

### 4.2 必须覆盖的场景

**核心业务必须100%覆盖**：
- 账务计算（金额、押金、退款）
- 夜审过账（房费计算、统计）
- 房态并发（防超卖）
- 退房结算（账务闭环）

**异常场景必须覆盖**：
- 参数校验失败
- 业务规则违反
- 数据不存在
- 并发冲突

     * 生成随机邮箱
     * 
     * @return 邮箱地址
     */

    }

     * 生成随机金额
     * 
     * @param min 最小值
     * @param max 最大值
     * @return 金额
     */
    public static BigDecimal generateRandomAmount(BigDecimal min, BigDecimal max) {
        return min.add(BigDecimal.valueOf(Math.random())
            .multiply(max.subtract(min)))
            .setScale(2, RoundingMode.HALF_UP);
    }
}

### 7.2 测试断言工具类

`java
/**
 * 测试断言工具类
 * <p>
 * 提供自定义断言方法
 * </p>
 */
public class TestAssertions {
    
    /**
     * 断言业务异常
     * 
     * @param executable 执行逻辑
     * @param expectedCode 预期错误码
     * @param expectedMessage 预期错误消息
     */
    public static void assertBusinessException(
            Executable executable, 
            String expectedCode, 
            String expectedMessage) {
        
        BusinessException exception = assertThrows(
            BusinessException.class, 
            executable
        );
        
        assertEquals(expectedCode, exception.getCode());
        assertEquals(expectedMessage, exception.getMessage());
    }
    
    /**
     * 断言时间在范围内
     * 
     * @param actual 实际时间
     * @param expected 预期时间
     * @param toleranceSeconds 容差秒数
     */
    public static void assertDateTimeCloseTo(
            LocalDateTime actual, 
            LocalDateTime expected, 
            long toleranceSeconds) {
        
        long diffSeconds = Math.abs(
            Duration.between(actual, expected).getSeconds()
        );
        
        assertTrue(
            diffSeconds <= toleranceSeconds,
            String.format("时间差 %d 秒超过容差 %d 秒", diffSeconds, toleranceSeconds)
        );
    }
}
`

## 12. 测试最佳实践

### 12.1 测试命名
- 使用中文描述测试场景
- 使用下划线分隔场景和预期结果
- 示例：	estGetById_当ID存在时_返回账号信息

### 12.2 测试结构
- 遵循AAA模式（Arrange-Act-Assert）
- 每个测试只测试一个场景
- 测试之间相互独立

### 12.3 测试数据
- 使用测试数据构建器
- 测试数据要独立
- 集成测试数据要回滚

### 12.4 Mock使用
- Mock外部依赖
- 验证方法调用
- Mock返回值要合理

### 12.5 断言
- 断言要充分
- 断言要具体
- 断言要有意义
