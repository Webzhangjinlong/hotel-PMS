### 2.5 方法调用注释

```java
public void createReservation(ReservationDTO dto) {
    // 【参数校验】校验预订日期和房型信息
    validateReservationParams(dto);
    
    // 【库存检查】检查目标日期房型是否有可用房间
    RoomInventory inventory = roomInventoryService.checkAvailability(
        dto.getRoomTypeId(), 
        dto.getCheckInDate(), 
        dto.getCheckOutDate()
    );
    
    // 【防超卖】使用行锁锁定库存，防止并发超卖
    boolean locked = roomInventoryService.lockInventory(inventory.getId());
    if (!locked) {
        throw new BusinessException("房间已被其他用户预订，请重新选择");
    }
    
    try {
        // 【创建预订单】生成预订记录
        Reservation reservation = buildReservation(dto);
        reservationMapper.insert(reservation);
        
    } finally {
        // 【释放锁】无论成功失败都要释放库存锁
        roomInventoryService.unlockInventory(inventory.getId());
    }
}
```

## 3. 文件编码规范（强制）

### 3.1 UTF-8 编码（无BOM）

**重要**：所有 Java 文件必须使用 **UTF-8 无 BOM** 编码。

**问题描述**：
- UTF-8 BOM（Byte Order Mark）是文件开头的特殊字符 `\ufeff`
- Java 编译器不支持带有 BOM 的 UTF-8 文件
- 会导致编译错误：`java: 非法字符: '\ufeff'`

**解决方案**：
1. 使用 IDE 时，设置文件编码为 UTF-8（无 BOM）
2. 使用文本编辑器时，选择"UTF-8 无 BOM"编码
3. 如果文件已有 BOM，使用工具去除或重新创建文件

**检查方法**：
```powershell
# 检查文件是否有BOM（PowerShell）
$bytes = [System.IO.File]::ReadAllBytes("path/to/file.java")
if ($bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
    Write-Host "文件包含BOM"
}
```

## 4. 依赖管理规范

### 4.1 Maven 依赖原则

**分层依赖**：
```
pms-api → pms-service → pms-dao → pms-common
```

**禁止跨层依赖**：
- pms-service 不得依赖 pms-api
- pms-dao 不得依赖 pms-service
- pms-common 不得依赖其他模块

**跨层类的处理**：
- DTO 类放在 pms-common/dto
- 工具类放在 pms-common/utils
- 常量类放在 pms-common/constant
- 枚举类放在 pms-common/enums

### 4.2 依赖版本管理

所有依赖版本在父 POM 的 `<dependencyManagement>` 中统一管理：

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>${spring-boot.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>
```

## 7. 异常处理规范

### 7.1 业务异常
```java
// ✅ 正确：抛出自定义业务异常
throw new BusinessException(ResultCode.USER_NOT_FOUND);

// ❌ 错误：抛出通用异常
throw new RuntimeException("用户不存在");
```

### 7.2 异常捕获
```java
// ✅ 正确：捕获具体异常
try {
    // 业务逻辑
} catch (BusinessException e) {
    throw e;  // 业务异常继续抛出
} catch (Exception e) {
    log.error("系统异常", e);
    throw new BusinessException(ResultCode.SYSTEM_ERROR);
}

// ❌ 错误：捕获所有异常后忽略
try {
    // 业务逻辑
} catch (Exception e) {
    // 忽略异常
}
```

## 9. 数据库规范

### 9.1 表命名
- 表名：小写下划线，如 `sys_account`
- 字段名：小写下划线，如 `hotel_id`
- 主键：`id`
- 外键：`表名_id`，如 `hotel_id`

### 9.2 索引命名
- 普通索引：`idx_表名_字段`，如 `idx_room_hotel_id`
- 唯一索引：`uk_表名_字段`，如 `uk_room_no`

### 9.3 SQL 注释
```sql
-- 创建房间表
CREATE TABLE room (
    id BIGSERIAL PRIMARY KEY,               -- 主键ID
    hotel_id BIGINT NOT NULL,                -- 酒店ID
    room_type_id BIGINT NOT NULL,            -- 房型ID
    room_no VARCHAR(20) NOT NULL,            -- 房间号
    status VARCHAR(20) DEFAULT 'AVAILABLE'   -- 状态
);

-- 表注释
COMMENT ON TABLE room IS '房间表';

-- 字段注释
COMMENT ON COLUMN room.id IS '主键ID';
COMMENT ON COLUMN room.hotel_id IS '酒店ID';
```

## 13. 代码重构指南

### 13.1 重构原则
- **小步重构**：每次只做小的修改
- **保持功能**：重构不改变外部行为
- **测试先行**：重构前先写测试
- **持续重构**：不要等到最后才重构

### 13.2 常见重构场景
| 场景 | 重构方式 | 说明 |
|------|----------|------|
| 重复代码 | 提取方法/类 | 消除重复 |
| 长方法 | 拆分方法 | 提高可读性 |
| 大类 | 拆分职责 | 单一职责 |
| 魔法数字 | 提取常量 | 提高可维护性 |
| 深层嵌套 | 提前返回 | 减少嵌套 |
| 复杂条件 | 提取方法 | 提高可读性 |

### 13.3 重构步骤
1. 确认现有测试通过
2. 进行小的修改
3. 运行测试确认通过
4. 提交代码
5. 重复以上步骤
