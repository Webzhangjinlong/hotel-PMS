## 1. 技术栈

与 OTA 系统技术栈完全一致，但代码仓库、数据库、发布流程完全独立：

- 后端：Java 17、Spring Boot 3.3.5、MyBatis-Plus 3.5.7、PostgreSQL 17、Redis 7、Flyway
- 前端：Vue 3、Vite、ECharts、lucide-vue-next
- 接口：RESTful + `Result<T>` 统一返回 + Swagger（springdoc）
- 鉴权：JWT（HMAC-SHA256 自签名实现）+ 角色注解

## 2. 工程结构

```
pms-hotel/
├── pom.xml            # 父 POM
├── pms-common/        # 常量、异常、Result、工具类（纯 POJO）
├── pms-dao/           # Entity、Mapper、Flyway、MyBatis-Plus 配置
├── pms-service/       # 业务逻辑：认证、主数据、预订、入住退房、账务、夜审等
├── pms-api/           # Controller、DTO、拦截器、全局异常、Swagger
└── pms-web/           # Vue 3 前端（独立工程）
```

分层依赖：`api → service → dao → common`，包名 `com.hotel.pms.*`。

## 3. 数据库设计

独立数据库 `hotel_pms`，核心表：

| 表 | 说明 |
|---|---|
| hotel / hotel_floor | 酒店与楼层 |
| room_type / room | 房型与房间 |
| room_price / room_status_log | 日历价与房态变更历史 |
| reservation | 预订单 |
| stay / stay_guest | 入住单与入住人 |
| guest | 客人档案 |
| police_upload_log | 公安上传记录 |
| folio / fin_transaction / payment | 账务单、流水、支付 |
| night_audit | 夜审 |
| shift | 交接班 |
| operation_log | 操作日志 |
| sys_account | 系统账号 |
| integration_outbox / integration_event_log / integration_channel_config | 集成契约相关 |

关键约束：

- 房间、房型、楼层按酒店隔离，统一逻辑删除 `deleted`
- `stay` 对同一房间在住状态建立部分唯一索引，保证同一房间只有一个在住单
- `fin_transaction` 只增不改，冲账通过 `REVERSAL` 流水实现
- 身份证、渠道密钥等敏感字段 AES-GCM 加密存储

## 5. 与 OTA 系统的对接契约（预留）

本轮 OTA 系统不做变更，PMS 侧先行实现契约能力，通过配置开关控制：

### 5.1 出站事件

| 事件 | 触发时机 |
|---|---|
| HotelChanged | 酒店主数据变更 |
| RoomTypeChanged | 房型变更 |
| RoomChanged | 房间变更 |
| PriceChanged | 价格变更 |
| RoomStatusChanged | 房态变更 |
| StayCheckedIn | 入住 |
| StayCheckedOut | 退房 |
| ReservationChanged | 预订变更 |

事件信封：`{ eventId, type, occurredAt, payload }`。

投递保证：写业务事务时同时写入 `integration_outbox`，调度器按批次投递；接收端以 `eventId` 幂等；失败按 1/3/5 秒退避重试，超过 5 次标记失败并支持人工重放。

### 5.2 入站订单

`POST /api/v1/integration/orders` 接收渠道订单，以 `channelOrderNo` 唯一去重并自动生成 PMS 预订。本轮默认关闭，提供模拟通道验证。

### 5.3 安全

appId/appSecret + HMAC 签名 + 时间戳防重放；双方账号体系完全独立。

## 6. 并发、安全与性能

- 防超卖：预订创建事务内行锁校验，同一房间并发入住唯一索引兜底
- 夜审：Redis 分布式锁保证单实例执行，数据库唯一约束兜底
- 金额：BigDecimal，禁止浮点运算
- 操作日志：关键操作落 `operation_log`
- 性能预算：房态看板 150 间 3 秒内；前台操作 1 秒内；夜审 150 间 60 秒内；支持 500+ 家酒店在线

## 7. 部署

- 独立 Nginx + Spring Boot JAR，2C4G 起步
- PostgreSQL/Redis 可与 OTA 共用机器，但使用独立库、独立连接
- 配置通过环境变量注入：`PMS_DB_URL`、`PMS_DB_USERNAME`、`PMS_DB_PASSWORD`、`PMS_AUTH_TOKEN_SECRET` 等

## 8. 测试计划

- 单元测试：账务计算、夜审过账、房态并发、可售库存、退房结算、交接班核对
- 集成测试：公安重试、事件 outbox 幂等投递、并发入住、预订取消释放库存
- 本轮不包含真实 OTA 联调，仅通过模拟通道验证 PMS 侧契约

## 11. 安全设计

### 11.1 认证安全
| 安全措施 | 实现方式 | 说明 |
|----------|----------|------|
| 密码加密 | BCrypt | 密码不可逆加密存储 |
| Token认证 | JWT (HMAC-SHA256) | 无状态认证，有效期24小时 |
| 验证码 | 图形验证码 | 防止暴力破解 |
| 登录锁定 | 5次失败锁定30分钟 | 防止密码猜测 |

### 11.2 数据安全
| 安全措施 | 实现方式 | 说明 |
|----------|----------|------|
| 敏感数据加密 | AES-GCM | 身份证、渠道密钥等 |
| SQL注入防护 | MyBatis-Plus参数化查询 | 防止SQL注入 |
| XSS防护 | 前端输入过滤 | 防止跨站脚本攻击 |
| CSRF防护 | Token验证 | 防止跨站请求伪造 |

### 11.3 接口安全
| 安全措施 | 实现方式 | 说明 |
|----------|----------|------|
| 权限控制 | RBAC + 注解 | 角色和权限双重控制 |
| 接口限流 | 令牌桶算法 | 防止接口滥用 |
| 参数校验 | Bean Validation | 防止非法参数 |
| 操作日志 | AOP切面 | 记录关键操作 |

### 11.4 传输安全
| 安全措施 | 实现方式 | 说明 |
|----------|----------|------|
| HTTPS | TLS 1.2+ | 加密传输 |
| 请求签名 | HMAC签名 | 防止篡改 |
| 时间戳 | 请求时间校验 | 防止重放攻击 |

## 13. 灾备方案

### 13.1 数据备份
| 备份类型 | 频率 | 保留时间 | 存储位置 |
|----------|------|----------|----------|
| 全量备份 | 每天 | 30天 | 本地+云端 |
| 增量备份 | 每小时 | 7天 | 本地 |
| 事务日志 | 实时 | 7天 | 本地 |

### 13.2 数据恢复
| 恢复场景 | 恢复方式 | 恢复时间 |
|----------|----------|----------|
| 数据库损坏 | 全量恢复 | < 1小时 |
| 数据误删 | 增量恢复 | < 30分钟 |
| 数据回滚 | 事务日志 | < 10分钟 |

### 13.3 服务高可用
| 组件 | 高可用方案 | 说明 |
|------|------------|------|
| 应用服务 | 多实例部署 | 负载均衡 |
