## 1. 接口规范

### 1.1 请求规范

**请求头**：
```
Content-Type: application/json
Authorization: Bearer {token}
```

**请求方式**：
| 方式 | 用途 | 示例 |
|------|------|------|
| GET | 查询数据 | GET /api/v1/accounts/1 |
| POST | 创建数据 | POST /api/v1/accounts |
| PUT | 更新数据 | PUT /api/v1/accounts/1 |
| DELETE | 删除数据 | DELETE /api/v1/accounts/1 |

### 1.2 响应规范

**统一响应格式**：
```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1691472000000
}
```

**响应码说明**：
| 响应码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 1.3 分页规范

**分页请求参数**：
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | Integer | 否 | 页码，默认1 |
| size | Integer | 否 | 每页条数，默认10 |
| sort | String | 否 | 排序字段 |
| order | String | 否 | 排序方式：asc/desc |

**分页响应格式**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "records": [],
    "total": 100,
    "page": 1,
    "size": 10,
    "pages": 10
  }
}
```

## 2. 认证接口

### 2.1 用户登录

**接口**：POST /api/v1/auth/login

**接口描述**：用户登录认证，获取JWT令牌

**请求参数**：
```json
{
  "username": "admin",
  "password": "123456",
  "captcha": "1234",
  "captchaKey": "captcha_key_123"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | String | 是 | 用户名，长度3-50 |
| password | String | 是 | 密码，长度6-100 |
| captcha | String | 是 | 验证码 |
| captchaKey | String | 是 | 验证码key |

**响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "userInfo": {
      "id": 1,
      "username": "admin",
      "realName": "管理员",
      "role": "ADMIN",
      "hotelId": 1
    }
  }
}
```

**错误响应**：
| 错误码 | 说明 |
|--------|------|
| AUTH_001 | 用户名或密码错误 |
| AUTH_002 | 验证码错误或已过期 |
| AUTH_003 | 账号已被锁定 |
| AUTH_004 | 账号已被停用 |

### 2.2 获取当前用户信息

**接口**：GET /api/v1/auth/current

**接口描述**：获取当前登录用户信息

**请求头**：
```
Authorization: Bearer {token}
```

**响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "realName": "管理员",
    "phone": "13800138000",
    "email": "admin@example.com",
    "role": "ADMIN",
    "hotelId": 1,
    "hotelName": "测试酒店"
  }
}
```

### 2.3 退出登录

**接口**：POST /api/v1/auth/logout

**接口描述**：退出登录，使token失效

**响应数据**：
```json

  "code": 200,
  "message": "success",
  "data": null
```

**接口**：GET /api/v1/auth/captcha

**接口描述**：获取登录验证码

**接口**：PUT /api/v1/stays/extend

**接口描述**：客人续住，延长住宿时间。系统会自动检查房间可用性并计算续住费用。

**请求参数**：
```json
{
  "stayId": 1,
  "newCheckOutDate": "2026-08-15"
}
```

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| stayId | Long | 是 | 入住单ID |
| newCheckOutDate | String | 是 | 新离店日期，格式：YYYY-MM-DD，必须大于当前离店日期 |

**响应数据**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "stayId": 1,
    "stayNo": "S202608090001",
    "oldCheckOutTime": "2026-08-12T12:00:00",
    "newCheckOutTime": "2026-08-15T12:00:00",
    "extendedDays": 3,
    "additionalAmount": 1164.00,
    "newTotalAmount": 2328.00
  }
}
```

| 参数 | 类型 | 说明 |
|------|------|------|
| stayId | Long | 入住单ID |
| stayNo | String | 入住单号 |
| oldCheckOutTime | String | 原离店时间 |
| newCheckOutTime | String | 新离店时间 |
| extendedDays | Integer | 续住天数 |
| additionalAmount | BigDecimal | 新增费用 |
| newTotalAmount | BigDecimal | 新总金额 |

**业务规则**：
1. 只有在住状态（CHECKED_IN）的入住单才能续住
2. 新离店日期必须大于当前离店日期
3. 系统会检查续住期间房间是否被其他入住或预订占用
4. 续住费用按每日房价自动计算并累加到总金额
5. 自动更新关联的账务单

**错误响应**：
| 错误码 | 说明 |
|--------|------|
| STAY_001 | 入住单不存在 |
| STAY_002 | 只有在住状态才能续住 |
| STAY_003 | 新离店日期必须大于当前离店日期 |
| STAY_004 | 该房间在续住期间已被占用 |
| STAY_005 | 该房间在续住期间已有预订 |

## 23. RBAC权限系统说明

### 23.1 数据库表

| 表名 | 说明 |
|------|------|
| sys_account | 用户表 |
| sys_role | 角色表 |
| sys_permission | 权限表 |
| sys_user_role | 用户角色关联表 |
| sys_role_permission | 角色权限关联表 |

### 23.2 默认角色

| 角色编码 | 角色名称 | 说明 |
|----------|----------|------|
| SUPER_ADMIN | 超级管理员 | 拥有所有权限 |
| HOTEL_ADMIN | 酒店管理员 | 管理酒店日常运营 |
| MANAGER | 店长 | 管理前台和房务 |
| RECEPTIONIST | 前台接待 | 处理预订和入住 |
| FINANCE | 财务人员 | 管理账务和报表 |

### 23.3 权限编码规范

```
资源类型:操作:资源

示例：
├── menu:dashboard              # 菜单：工作台
├── menu:reservation            # 菜单：预订管理
├── button:reservation:create   # 按钮：创建预订
├── button:reservation:cancel   # 按钮：取消预订
└── api:/api/v1/reservations    # 接口：预订接口
```

### 23.4 权限校验注解

**角色校验**：
```java
@RequiresRole({"SUPER_ADMIN", "HOTEL_ADMIN"})
@GetMapping("/api/v1/accounts")
public Result<List<AccountVO>> list() {
    // 只有管理员可以访问
}
```

**权限校验（OR逻辑）**：
```java
@RequiresPermission({"reservation:create", "reservation:edit"})
@PostMapping("/api/v1/reservations")
public Result<ReservationVO> create() {
    // 有创建或编辑预订权限即可访问
}
```

**权限校验（AND逻辑）**：
```java
@RequiresPermission(value = {"reservation:create", "reservation:edit"}, logical = RequiresPermission.Logical.AND)
public Result<ReservationVO> create() {
    // 需要同时有创建和编辑权限
}
```

### 26.1 限流策略
| 接口类型 | 限流规则 | 说明 |
|----------|----------|------|
| 登录接口 | 5次/分钟 | 防止暴力破解 |
| 查询接口 | 100次/分钟 | 防止滥用 |
| 写入接口 | 30次/分钟 | 防止恶意操作 |

### 26.2 限流算法
- **算法**：令牌桶算法
- **实现**：Redis + Lua脚本
- **粒度**：基于用户ID或IP地址

`json
{

  "message": "请求过于频繁，请稍后再试",
  "data": null,
  "timestamp": 1691472000000
}
`

rate-limit:
