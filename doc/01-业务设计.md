# PMS 酒店管理系统业务设计文档

**版本**：v1.0  
**最后更新**：2026-08-20  
**状态**：定稿

---

## 1. 产品定位

面向 **150 间房规模的中型酒店**（含单体酒店和中小连锁）的前台运营系统，覆盖预订、入住、房态、账务、夜审、公安上传和经营报表。系统以 Web 管理端为主，前台操作密集场景下要求稳定、高效、防超卖。

PMS 与已有 OTA 渠道管理系统为两套完全独立的系统：独立前端、独立后端、独立数据库、独立发布。本轮 OTA 系统不做任何变更，双方对接契约先行设计，PMS 侧实现可开关的推送/接收能力，OTA 侧改造后激活。

## 2. 目标用户

| 角色 | 使用场景 | 核心诉求 |
|---|---|---|
| 前台 | 预订、入住、退房、收银、房务、公安登记 | 快、准、不超卖 |
| 店长/老板 | 夜审、报表、交接班核对、经营管理 | 数据准确、口径一致 |
| 管理员 | 酒店主数据、账号权限、系统配置 | 可控、可审计 |

## 3. 核心业务对象

- `reservation` 预订单：来源（电话/散客/未来 OTA）、日期、房型、价格、状态
- `stay` 入住单：一间房一段在住记录，由预订入住或直接散客入住产生
- `folio + fin_transaction` 账务：押金、房费、杂费、付款、退款、冲账流水
- `room + room_status_log` 房态：房间状态与变更历史
- `guest + stay_guest + police_upload_log` 客人登记与公安上传
- `night_audit` 夜审：每日结业、自动过账、营业统计
- `room_price` 价格：房型基础价与日历价

## 4. 主流程

```
预订（电话/散客/未来 OTA）
  → 抵店入住
  → 登记客人并公安上传
  → 收押金、分房
  → 住中：续住/换房/加杂费
  → 夜审自动过账房费
  → 退房结账、退款
  → 脏房 → 查房 → 净房可售
```

OTA 线（契约预留，本轮未激活）：

```
渠道订单到达 → 自动生成 PMS 预订 → 到店入住
  → 入住/退房事件推送渠道系统
  → 渠道系统回写 OTA 平台
```

## 5. 关键业务规则

| 主题 | 规则 |
|---|---|
| 房态 | 按楼层/分区组织；状态分空闲、在住、脏房、维修、OOO、预留；展示优先级为在住 > 维修 > 脏房 > 空闲 |
| 可售 | 可售条件为净房、空闲、无预留占用；可用房量由 PMS 统一计算 |
| 防超卖 | 预订创建即占用对应日期房型库存，事务内行锁校验；同一房间并发入住只能成功一次 |
| 计费 | 房费由夜审按间夜自动过账；默认离店 12:00，12:00-18:00 超时收半日租，18:00 后收全日租，参数可配置 |
| 账务 | 金额使用 Decimal(10,2)；流水只增不改，错误用冲账流水纠正，禁止物理删除 |
| 公安 | 入住时必须采集姓名、证件号、手机号、入住时间并上传公安；失败进入重试队列，支持人工补传 |
| 夜审 | 默认每日 04:00 结业；自动过房费、统计营业日报、锁定当日数据；150 间房全量过账控制在 60 秒内 |
| 交接班 | 交接班时冻结并核对当班收银流水；未结账务可跨班继续处理 |
| 权限 | 管理员、店长、前台三类角色，权限控制到页面和关键操作 |
| 时区 | 统一使用 Asia/Shanghai |

## 6. 与 OTA 系统的边界

- PMS 是酒店主数据、房态、价格、订单状态的唯一真源。
- OTA 系统只消费 PMS 推送的数据，并负责渠道映射、配额、同步日志、佣金分析。
- 公安上传留在 PMS，不推送到 OTA 渠道；渠道侧需要的是入住/退房订单状态。
- 跨系统数据：酒店、房型、房间主数据，房态，价格，入住退房事件，渠道订单。

## 10. 异常处理流程

### 10.1 预订异常
| 异常类型 | 处理方式 | 影响 |
|----------|----------|------|
| 房间超卖 | 拒绝预订，提示无房 | 预订失败 |
| 价格异常 | 使用基础价，记录日志 | 价格可能不准确 |
| 重复预订 | 检查客人信息，提示重复 | 需人工确认 |

### 10.2 入住异常
| 异常类型 | 处理方式 | 影响 |
|----------|----------|------|
| 房间不可用 | 提示房间状态异常 | 需检查房态 |
| 公安上传失败 | 进入重试队列 | 可能影响合规 |
| 支付失败 | 提示支付异常 | 需人工处理 |

### 10.3 退房异常
| 异常类型 | 处理方式 | 影响 |
|----------|----------|------|
| 账务不平 | 提示账务异常 | 需核对账务 |
| 房间损坏 | 记录损坏情况 | 可能产生赔偿 |
| 超时退房 | 按规则收费 | 可能产生额外费用 |

### 10.4 夜审异常
| 异常类型 | 处理方式 | 影响 |
|----------|----------|------|
| 过账失败 | 重试3次，失败则记录 | 可能影响日报 |
| 数据锁定失败 | 提示数据被占用 | 需等待解锁 |
| 统计异常 | 使用默认值，记录日志 | 统计可能不准确
